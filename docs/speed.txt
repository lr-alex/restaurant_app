Saffron & Stone REST API Speed Test
===================================

Use PowerShell terminals. Do not paste commands into the browser address bar.

The tested one-command runner is:

    npm run test:api

It exercises the same session, role, Branch status, booking, order, Staff
authorization, and Admin CRUD paths used by the application.

    cd D:\study\hkmu\comp_3810_sever-side\proj\restaurant_app

    npm start

    Accounts: customer1, customer2, staff1, staff2, admin1
    Database restored to the pre-CRUD demo baseline.
    Saffron & Stone listening at http://localhost:8099

5. Manual login check with PowerShell
-------------------------------------

If the automated script cannot connect, test the server first:

    curl.exe -s -o NUL -w "%{http_code}" `
      http://localhost:8099/api/branches

Expected:

    401

Now log in using PowerShell native JSON and a real WebRequestSession:

    $session = New-Object Microsoft.PowerShell.Commands.WebRequestSession

    $body = @{
      username = "customer1"
      password = "Customer@123"
    } | ConvertTo-Json -Compress

    $request = @{
      Method = "POST"
      Uri = "http://localhost:8099/api/session"
      WebSession = $session
      ContentType = "application/json"
      Body = $body
      UseBasicParsing = $true
    }

    Invoke-WebRequest @request

Expected:

    201 Created

Check the stored session:

    $currentSession = Invoke-RestMethod `
      -Uri "http://localhost:8099/api/session" `
      -WebSession $session

The default table view may collapse the nested profile to "@{...}". Print the
complete response:

    $currentSession | ConvertTo-Json -Depth 5

Print the profile fields explicitly:

    $currentSession.data.profile | Format-List

Expected JSON:

    {
      "data": {
        "username": "customer1",
        "role": "customer",
        "profile": {
          "id": "MONGODB_OBJECT_ID",
          "name": "Bob Johnson",
          "branchNo": null
        }
      }
    }

Expected profile fields:

    id       : MONGODB_OBJECT_ID
    name     : Bob Johnson
    branchNo :


6. Why the old login command returned 400
-----------------------------------------

This command is unreliable in Windows PowerShell 5.1:

    curl.exe --data-raw '{"username":"customer1","password":"Customer@123"}'

PowerShell can remove the JSON double quotes before curl receives the argument.
The server then responds with:

    400 Bad Request
    Expected property name or '}' in JSON

Use the tested `scripts/api-speed.ps1` script, or build the body with
`ConvertTo-Json` and pass it as a PowerShell object/body.

The speed script uses `Invoke-WebRequest` and `ConvertTo-Json`, so it does not
depend on browser interaction, curl aliases, or command-line JSON quoting.
