Saffron & Stone REST API Test — Detailed PowerShell Steps
===========================================================

This file contains the tested Windows PowerShell procedure for exercising the
REST API. Run these commands in a PowerShell terminal, not in the browser
address bar.

The procedure was tested against the current application on a temporary port.
Use port 8099 below for the normal local setup.


0. Important PowerShell rule
----------------------------

Use curl.exe, not the PowerShell alias named curl.

Do not send JSON with --data-raw when the JSON is stored in a PowerShell
variable on Windows PowerShell 5.1. PowerShell can remove the inner double
quotes and the API receives malformed JSON.

Reliable pattern:

    $body = @{ key = "value" } | ConvertTo-Json -Compress
    $body | curl.exe ... -H "Content-Type: application/json" --data-binary "@-"

The request body is piped to curl through standard input. This avoids command
line quoting problems.


1. Prepare the application
--------------------------

In the first PowerShell terminal:

    cd D:\study\hkmu\comp_3810_sever-side\proj\restaurant_app
    npm run reset
    npm start

Expected:

    Demo reset complete.
    Accounts: customer1, customer2, staff1, staff2, admin1
    Database restored to the pre-CRUD demo baseline.
    Saffron & Stone listening at http://localhost:8099

Leave this terminal running. Open a second PowerShell terminal for the API
requests.

If you changed the port, set the matching base URL:

    $base = "http://localhost:8099"


2. Verify that authentication is required
-----------------------------------------

    $base = "http://localhost:8099"
    curl.exe -s -o NUL -w "%{http_code}" "$base/api/branches"

Expected:

    401

This proves that API resources are protected by the session.


3. Create separate Cookie files
-------------------------------

    $tmp = $env:TEMP
    $customerCookies = Join-Path $tmp "saffron-customer-cookies.txt"
    $staffCookies = Join-Path $tmp "saffron-staff-cookies.txt"
    $staff2Cookies = Join-Path $tmp "saffron-staff2-cookies.txt"
    $adminCookies = Join-Path $tmp "saffron-admin-cookies.txt"

Use a different Cookie file for each role so the sessions do not overwrite
each other.


4. Sign in as Customer 1
------------------------

    $loginBody = @{
      username = "customer1"
      password = "Customer@123"
    } | ConvertTo-Json -Compress

    $customerLoginStatus = $loginBody | curl.exe -s -o NUL -w "%{http_code}" `
      -c $customerCookies `
      -X POST "$base/api/session" `
      -H "Content-Type: application/json" `
      --data-binary "@-"

    $customerLoginStatus

Expected:

    201

To see the complete response and Set-Cookie header:

    $loginBody | curl.exe -s -i `
      -c $customerCookies `
      -X POST "$base/api/session" `
      -H "Content-Type: application/json" `
      --data-binary "@-"

Verify the current session:

    curl.exe -s -b $customerCookies "$base/api/session" | ConvertFrom-Json

Expected:

    username = customer1
    role = customer
    profile.name = Bob Johnson


5. Read Branch operating status
-------------------------------

    $branches = (
      curl.exe -s -b $customerCookies "$base/api/branches" |
      ConvertFrom-Json
    ).data

    $branches |
      Select-Object branchNo, name, operatingStatus

Expected:

    Branch 1 = active
    Branch 2 = resting
    Branch 3 = active
    Branch 4 = active

GET /api/branches is a read-only endpoint. Branch status changes are performed
through the administrator web interface.


6. Read the meal catalog
------------------------

    $meals = (
      curl.exe -s -b $customerCookies "$base/api/meals" |
      ConvertFrom-Json
    ).data

    $meals | Select-Object name, category, price
    $mealId = $meals[0]._id
    $mealId

The returned _id is a MongoDB ObjectId. Keep it in $mealId for the order test.


7. Create a valid booking on Branch 1
-------------------------------------

Build a future date that is not Monday, because Branch 1 rests on Monday:

    $bookingDate = (Get-Date).Date.AddDays(7)
    while ($bookingDate.DayOfWeek -eq "Monday") {
      $bookingDate = $bookingDate.AddDays(1)
    }

    $bookingBody = @{
      branchNo = 1
      bookingDate = $bookingDate.ToString("yyyy-MM-dd")
      slotStart = "19:00"
      slotEnd = "21:00"
      partySize = 2
      notes = "speed.txt API test"
    } | ConvertTo-Json -Compress

    $booking = (
      $bookingBody | curl.exe -s `
        -b $customerCookies `
        -X POST "$base/api/bookings" `
        -H "Content-Type: application/json" `
        --data-binary "@-" |
      ConvertFrom-Json
    ).data

    $bookingId = $booking._id

    $booking |
      Select-Object _id, branchNo, bookingDate, slotStart, slotEnd,
        partySize, status

Expected:

    status = pending
    branchNo = 1

Read the created booking:

    curl.exe -s -b $customerCookies `
      "$base/api/bookings/$bookingId" |
      ConvertFrom-Json


8. Test duplicate-booking protection
------------------------------------

Send the same booking body again:

    $duplicateStatus = $bookingBody | curl.exe -s -o NUL -w "%{http_code}" `
      -b $customerCookies `
      -X POST "$base/api/bookings" `
      -H "Content-Type: application/json" `
      --data-binary "@-"

    $duplicateStatus

Expected:

    409

The server rejects a second active booking for the same customer, branch,
date, and slot.


9. Test a resting Branch
------------------------

    $restingBookingBody = @{
      branchNo = 2
      bookingDate = (Get-Date).Date.AddDays(10).ToString("yyyy-MM-dd")
      slotStart = "10:00"
      slotEnd = "12:00"
      partySize = 2
    } | ConvertTo-Json -Compress

    $restingBookingStatus = $restingBookingBody | curl.exe `
      -s -o NUL -w "%{http_code}" `
      -b $customerCookies `
      -X POST "$base/api/bookings" `
      -H "Content-Type: application/json" `
      --data-binary "@-"

    $restingBookingStatus

Expected:

    404

Branch 2 exists and is visible, but its operatingStatus is resting, so it is
not an available booking target.


10. Create an order on Branch 1
-------------------------------

Do not send totalAmount or unitPrice. The server calculates both.

    $orderBody = @{
      branchNo = 1
      items = @(
        @{
          mealId = $mealId
          quantity = 2
        }
      )
    } | ConvertTo-Json -Depth 5 -Compress

    $order = (
      $orderBody | curl.exe -s `
        -b $customerCookies `
        -X POST "$base/api/orders" `
        -H "Content-Type: application/json" `
        --data-binary "@-" |
      ConvertFrom-Json
    ).data

    $orderId = $order._id

    $order |
      Select-Object _id, branchNo, status, totalAmount, items

Expected:

    status = placed
    items contains a server-created meal name, unit price, quantity, subtotal
    totalAmount is calculated by the server

In the tested seed data with the first returned meal at quantity 2, the total
was 15.00.


11. Test ordering from the resting Branch

    $restingOrderBody = @{
      branchNo = 2
      items = @(
        @{
          mealId = $mealId

      -b $customerCookies `
      -X POST "$base/api/orders" `
      -H "Content-Type: application/json" `
      --data-binary "@-"

Expected:

    400

Branch 2 is resting and cannot accept new orders.


12. Sign in as Staff 1 and update the order
-------------------------------------------

    $staffLoginBody = @{
      username = "staff1"
      password = "Staff@123"
    } | ConvertTo-Json -Compress

    $staffLoginStatus = $staffLoginBody | curl.exe `
      -s -o NUL -w "%{http_code}" `

Expected:

Update the new order:

    $updatedOrder = (
      $statusBody | curl.exe -s `
        -b $staffCookies `
        -X PATCH "$base/api/orders/$orderId" `

      ConvertFrom-Json

Expected:

    status = preparing


13. Test Staff branch isolation
-------------------------------

Staff 1 belongs to Branch 1 and must not query Branch 2 orders:

    $isolationStatus = curl.exe -s -o NUL -w "%{http_code}" `
      -b $staffCookies `
      "$base/api/orders?branchNo=2"

    $isolationStatus

Expected:

    403

-------------------------------

      -X DELETE "$base/api/bookings/$bookingId"

Expected:

Delete the temporary meal because it has no order history:

Common mistakes
---------------

1. Pasting curl.exe into the browser address bar.
   Use a PowerShell terminal instead.

2. Using curl instead of curl.exe.
   In PowerShell, curl may resolve to Invoke-WebRequest.

3. Using this pattern on Windows PowerShell:

       curl.exe --data-raw $json

   The JSON quotes can be lost. Use:

       $json | curl.exe --data-binary "@-"

4. Reusing the same Cookie file for two roles.
   Use one file per role.

5. Forgetting -b $cookies on protected requests.

6. Running the fixed December dates after they pass.
   Use the dynamic future-date code above.

7. Forgetting to run npm run reset after testing.
